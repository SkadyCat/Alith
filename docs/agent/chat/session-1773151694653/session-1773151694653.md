

## 🔍 transient API error 根本原因分析

### 错误来源

Request failed due to a transient API error. Retrying...

这是 **GitHub Copilot CLI 内置的重试机制**输出的消息，表示向 **Anthropic Claude API** 发起请求时收到了服务端瞬时错误（通常是 HTTP **529 Overloaded** 或 **503 Service Unavailable**）。

### 错误流程

`
Claude CLI 发起 API 请求
    → 服务端返回 529/503（过载/不可用）
    → CLI 内部自动重试（默认 5~6 次）
    → 全部重试失败 → 退出码 1
        → pyagent_server.js 检测到 code=1 + "transient API error"
        → 指数退避重启（10s → 20s → 40s → 80s...）
`

### 为什么最近频繁出现？

| 原因 | 说明 |
|------|------|
| 🕐 **晚高峰时段** | 19:00-21:00 是 Anthropic 全球 API 使用高峰，服务器经常过载 |
| 📋 **历史文件累积** | 测试Agent2.md 已达 **85 KB**，每次调用携带大量上下文，耗时更长、更易超时 |
| 🔁 **连续高频调用** | POLL 重启后立即调用，没有给 API 足够的恢复时间 |

### 当前防护机制（已就绪）

pyagent_server.js 中的指数退避已生效：
- 第 1 次：等待 10 秒
- 第 2 次：等待 20 秒
- 第 3 次：等待 40 秒
- 第 4 次：等待 80 秒
- 第 5 次：等待 160 秒
- 第 6 次及以后：等待 300 秒（5 分钟）

### 建议

1. **等待即可**：API 过载是暂时的，exponential backoff 会自动处理。
2. **检查 Clash 代理**：确认端口 7890 代理连通稳定，不稳定的代理会加剧超时。
3. **历史文件归档**：测试Agent2.md 已 85KB，可以考虑创建新 session 从零开始，减少每次调用的 token 量。
4. **避开高峰时段**：如非紧急任务，可以等到深夜或早晨（UTC 时间使用量低时）再运行。

### 无需修改代码

pyagent_server.js 的处理逻辑是正确的，exponential backoff 会在 API 恢复后自动恢复正常工作。


## 😤 为什么 transient API error 老是出现？能救不？

**能救，已经改了两处。** 下面是完整分析：

---

### 根本原因

Request failed due to a transient API error = **Anthropic 服务器过载**（HTTP 529）

Claude CLI 内部重试 5-6 次 → 全部失败 → 退出码 1

这是 **Anthropic 服务端的问题**，不是代码 bug。

---

### 为什么这么频繁？（3 个原因）

**① 历史文件超大**

| 文件 | 大小 |
|------|------|
| CanvasEditor.md | **1412 KB** 🔴 |
| 长记忆功能.md | 321 KB |
| 测试Agent2.md | 86 KB |

每次 API 调用都携带历史文件末尾内容（之前 8KB），token 多 → 响应慢 → 更易超时。

**② 高峰时段**

19:00-22:00 是 Anthropic 全球高峰期，529 错误概率大幅上升。

**③ 重启太快**

之前第一次失败只等 10 秒就重试，API 还没恢复就又打过去了。

---

### 本次修复（已热重载生效）

| 改动 | 之前 | 现在 |
|------|------|------|
| 历史文件截断长度 | 8000 字符 | **4000 字符**（减少 token） |
| 首次失败等待时间 | 10 秒 | **30 秒** |
| 指数退避序列 | 10s→20s→40s→80s→160s→300s | **30s→60s→120s→240s→300s** |

---

### 还能做什么？

1. **避开晚高峰** — 如果不急，等到 23:00 以后或早上
2. **检查 Clash 代理** — 端口 7890 不稳定会叠加超时
3. **CanvasEditor.md 归档** — 1.4MB 的历史文件可以另存为存档，从新文件开始

现在等待时间更长，API 有更多时间恢复，崩溃率应该会明显下降。 ✅


## 关于 "没有原因" 出现 transient API error

这个错误**确实没有你这边的原因** — 这是 Anthropic（Claude 的开发商）服务器端的问题，跟你的代码、网络或操作完全无关。

### 通俗解释

想象你打电话给客服：

- 你拨号（Claude CLI 发出 API 请求）
- 对方电话占线/忙音（Anthropic 服务器过载，返回 HTTP 529）
- 你重拨了 5 次（CLI 内部自动重试）
- 还是打不通 → 挂断（退出码 1）

**你没做错任何事**，只是服务器那边太忙了。

### 什么时候最容易出现？

- 北京时间 **19:00 - 23:00**（欧美白天，全球高峰）
- Anthropic 发布新模型/功能后的几天
- GitHub Copilot 大规模促销期间

### 已有的保护

pyagent_server.js 现在会这样处理：
1. 检测到 code=1 + "transient API error"
2. 等待 **30 秒**（之前是 10 秒）再重试
3. 如果还失败：60s → 120s → 240s → 300s
4. API 恢复后自动继续，无需手动干预

**结论：不需要做任何事，等它自动恢复就好。** ✅
