## 核心设计思路总览

### 问题原点
传统技能系统 = 每种技能一段硬编码 → 维护成本爆炸，无法组合。  
节点图框架的核心假设：**任何技能效果 = 触发源 → 传播载体 → 行为修饰 → 最终效果**

---

### 七类节点，各司其职

| 节点 | 回答的问题 | 例子 |
|------|----------|------|
| **Source** | 何时/如何激活？ | 主动施法、被动触发、光环脉冲 |
| **Delivery** | 效果怎么到达目标？ | 投射物、范围、光束、召唤 |
| **Modifier** | 载体如何运动？ | 穿透、弹跳、追踪、链式、分裂 |
| **Effect** | 到达后发生什么？ | 伤害、DoT、控制、标记、治愈 |
| **Condition** | 什么时候才触发？ | 命中时、暴击时、标记叠满时 |
| **Filter** | 哪些对象受影响？ | 仅敌方、仅低血量 |
| **Transform** | 数值如何转换？ | 放大、衰减、随机化 |

---

### 三条数据总线（连线语义）

`
exec 总线    = 控制流（"现在轮到你执行"）
signal 总线  = 事件总线（"某件事发生了，你可以响应"）
data 总线    = 数据流（传递数值/目标列表）
`

分三条总线的原因：让每条线的**语义清晰可见**，图结构即文档，便于静态分析和调试。

---

## 问题根源：双重白名单

当前系统在两个地方同时做了限制：

`
modifier.applies_to: ["projectile", "beam"]    ← 修饰符自己声明能用于哪些类型
delivery.compatible_modifiers: ["split","bounce"]  ← 载体再次声明允许哪些修饰符
`

这两个列表**必须同时通过**才算兼容，结果就是「分裂」根本无法用在「范围」上——即便在游戏设计上「范围分裂成多个小范围」完全合理。

---

## 更好的设计：能力标签系统（Capability Tags）

**核心思路**：不用 ID 白名单，改用「能力标签」判断兼容性。

### Delivery 声明它"有什么"

| 载体类型 | 能力标签 |
|---------|---------|
| 投射物 | has_trajectory（有轨迹）has_impact（有命中点） |
| 范围 | has_geometry（有形状）has_impact（有命中区域） |
| 持续场 | has_geometry has_timing（有持续时间） |
| 射线 | has_trajectory has_geometry has_timing |
| 即时 | has_impact is_instantaneous |
| 召唤 | has_entity（有实体） |

### Modifier 声明它"需要什么"

| 修饰符 | 需要的能力 | 兼容推导 |
|-------|----------|---------|
| 分裂 | has_impact | ✅ 投射物、范围、即时 全部兼容 |
| 弹跳 | has_trajectory | ✅ 投射物、射线；❌ 范围、持续 |
| 穿透 | has_trajectory has_impact | ✅ 投射物；❌ 范围（无轨迹） |
| 追踪 | has_trajectory | ✅ 投射物、射线 |
| 扩大 | has_geometry | ✅ 范围、持续、射线 全部兼容 |
| 脉冲 | has_timing | ✅ 持续、射线；❌ 投射物（无持续时间） |

### 冲突规则改为：语义不可能

只有**物理/逻辑上真正无意义**的组合才应该被禁止：

`json
"conflicts": ["homing + persistent"]  // 固定不动的场地，追踪谁？
"conflicts": ["pierce + area"]         // 范围已命中所有目标，穿透的意义？
`

而「范围 + 分裂」——**范围可以分裂成多个小范围**，完全合理，不应该被拦截。

---

## 对被动/反应技能的影响

eaction 源节点监听另一个技能的 signal，后续接一个 delivery。  
你说的问题是：这个 delivery 如果是「范围」，为什么范围相关的修饰符都不能用？

原因正是白名单太死。按新设计：
`
reaction source → area delivery（has_geometry, has_impact）
                       ↓
  cascade（需要 has_geometry）✅ 可用
  expand（需要 has_geometry）✅ 可用
  split（需要 has_impact）   ✅ 可用  ← 当前被错误拦截
  linger（需要 has_timing）  ❌ 不可（area 没有持续时间）
  homing（需要 has_trajectory）❌ 不可（area 无轨迹）
`

**范围能用的修饰符多了，但仍然有边界——边界由"你是什么"决定，而不是由"显式白名单"决定。**
