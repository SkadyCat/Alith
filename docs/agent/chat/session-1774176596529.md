## 分析结果：为什么 `pyagentStatusText` 一直显示"空闲"

**两个原因叠加：**

### 原因 A（更根本）：SSE 通道不匹配
- POLL 脚本调用 `POST /agent/set-status` → 广播 `session-status` 事件 → **走 `/agent/stream`**  
- `pyagentStatusText` 所在的 PyAgent 面板监听的是 **`/pyagent/stream`**（`public/app.js` 第 4767 行）
- 两条通道完全隔离，POLL 发出的状态**根本不会到达** pyagentStatusText

### 原因 B：状态映射缺少 `waiting` / `working`
即使消息真的到了 PyAgent 的 `es.onmessage`（第 4810 行），映射也只处理了：
```js
s === 'running' → '运行中'
s === 'done'    → '已完成'
s === 'error'   → '出错'
// 其他（含 'waiting', 'working'）→ 全部 fallthrough → '空闲'
```

### 触发链路
```
POLL → /agent/set-status → /agent/stream (session-status) → Agent面板 ✅
                                                           → PyAgent面板 ❌ (不同通道)
```

是的，**一定会错位**。这是我的完整分析和解决方案：

---

## 问题根源

当前 canvas-editor 所有坐标是**绝对像素**（设计分辨率 1280×960）。切换到 1920×1080 或 2560×1440 时，bagWidget 整体比例不变，但屏幕变大后容器位置漂移，内部元素没有锚点信息，全部错位。

---

## UMG Anchor 系统核心思路

UMG 用 4 个值描述锚点：
```
anchorMin: {x, y}   -- 锚点左上角（0~1，父容器归一化坐标）
anchorMax: {x, y}   -- 锚点右下角

当 anchorMin == anchorMax（点锚）：
  position = offset from anchor point（固定距离）
当 anchorMin != anchorMax（拉伸锚）：
  left/right/top/bottom = 边距（四边拉伸）
```

---

## 对 bag UI 的设计策略

| 节点 | 锚点方案 | 理由 |
|------|---------|------|
| `bagWidget` | `center` (0.5,0.5 / 0.5,0.5) | 整个背包面板居中于屏幕 |
| `statPanel`, `paperdollPanel`, `invPanel`, `beltPanel` | **左上角点锚** (0,0/0,0) + 固定偏移 | 相对 bagWidget 固定布局，内部不拉伸 |
| `hpBar`, `mpBar` 进度条 | **水平拉伸** (0,0.5 / 1,0.5) + 上下固定 | 随父容器宽度缩放 |
| `invGrid` TileView | **四边拉伸** (0,0 / 1,1) | 格子充满背包格区域 |
| 各种文字 Label | **左上点锚** | 固定距离父容器左上 |

---

## 我的解决方案

在 canvas-editor 的节点数据里增加 `anchor` 字段：

```json
{
  "id": "statPanel",
  "anchor": {
    "min": {"x": 0, "y": 0},
    "max": {"x": 0, "y": 0},
    "pivot": {"x": 0.5, "y": 0.5}
  }
}
```

**导出 UMG** 时，按 `anchor` 字段生成真实的 `UWidget` 锚点属性，而不是硬编码像素位置。

**预览时**，可以加一个"分辨率模拟"模式，将 canvas 缩放到目标分辨率，验证锚点是否正确。

2. **Step 2（后续）**：在 UMG 导出时用锚点生成代码；预览模式支持分辨率缩放验证
