# SOP：框架设计（Framework Design）

## 触发关键词
设计框架 | 底层框架 | 设计思路 | 架构设计 | 节点设计 | 系统设计

## 执行步骤

1. **读取现有设计文档**：扫描 `docs/application_doc/` 下相关目录，了解当前状态
2. **阅读已有 schema/examples**：理解数据结构和已有规范
3. **分析问题本质**：找出"为什么要这样设计"的根本原因（不是表面的"怎么做"）
4. **撰写设计思路文档**：
   - 核心哲学 / 问题原点
   - 分层模型（各层职责）
   - 数据流设计（信号/控制/数据总线）
   - 涌现机制（组合如何产生复杂效果）
   - 平衡机制
   - 可扩展性说明
   - 当前边界与未来方向
5. **保存到对应设计目录**：`docs/application_doc/.../design-thinking.md`
6. **在会话历史追加结构化摘要**：表格+代码块形式，便于用户快速阅读

## 输出规范
- 文档结构：哲学 → 分层 → 数据流 → 组合示例 → 平衡 → 扩展 → 边界
- 摘要回复：用表格呈现节点分类，用代码块展示结构，不超过 80 行
- 不写伪代码实现，只写设计决策和理由
